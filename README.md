# 気温・湿度・絶対湿度

現在地の気温・相対湿度・**絶対湿度**を、実況と予報で表示するアプリです。
ビルド不要の静的ファイル（HTML／CSS／JavaScript）だけでできています。

**https://hironishimura.github.io/weather-absolute-humidity/**

相対湿度だけでは空気の乾き具合が分かりにくいため、
重量絶対湿度（g/kg(DA)）を主役に据えています。空気線図と同じ量で、暖めても冷やしても値が変わらないため、
換気量や結露を考えるときに扱いやすい指標です。容積絶対湿度（g/m³）も併記します。

## 表示するもの

- **気温**／**相対湿度**／**絶対湿度（g/kg(DA)）** … 大きく3つ。
  **取れている提供元の値を項目ごとに平均**したものです（提供元ごとの値はその下のカードに出ます）。
  実況と予報が混ざることがあります
- 容積絶対湿度（g/m³）・露点温度・現地気圧・風・前1時間降水量・不快指数
- 提供元ごとの値をカードで比較（実況値／予報値の区別と、いつの値かを明記）
- **時系列グラフ** … 直近1時間の実況とこれからの予報を**ひとつの軸に重ねて**表示
  （気温・相対湿度・絶対湿度・降水確率・雨量の5段、表示範囲は1〜7日）
  - 雨量は棒で出します。縦軸は0から始まります。提供元ごとに横へずらして並べます
  - 雨量の刻みは提供元で違います（Yahoo!天気は3時間ごとの合計）。
    そのまま並べると3時間ぶんの棒だけ高く見えるので、**1時間あたりに割って**そろえています
  - 横軸に日付と時刻、縦の線で日の区切りを入れています。
    時刻の刻みは表示範囲と画面幅に合わせて 1〜24時間おきで自動的に決まります
    （広い画面なら1日・2日は3時間おき、3日は6時間おき）
  - 縦軸の目盛りはキリのよい数字に丸めています
  - 気温のグラフには、気象庁の**日ごとの最高／最低気温と天気**を重ねています
  - 降水確率は4社ぶん重ねています。刻みは提供元で違うため階段の幅が変わります
    （気象庁6時間・Yahoo!天気6時間・ウェザーニュース午前午後・数値予報1時間）。
    その先は週間予報の日ごとの値で埋めます
- **1週間の予報を提供元ごとに並べた表**（天気・最高／最低気温・降水確率・絶対湿度の幅）。今日以降だけを出します
- **提供元ごとの色を変えられます**（グラフの「色を変える」から。この端末に保存されます）
- 気象庁の日別予報（3日＋週間）と気象概況
- **降水確率の当たり具合** … 各社の降水確率が実際に当たったかを数えます。
  7日前〜4日前は1日ごと、直近3日は半日ごと（午前・午後）。正解率とブライアスコア、
  期間ごとの内訳を出します
- **結露チェック** … 窓や壁の表面温度を入れると、露点と比べて結露するかどうかを判定します

**地点はいくつでも登録できます。** 名前と緯度・経度を入れて「新しい地点として追加」すると
上のボタンが増え、押すだけで切り替わります。登録内容はこの端末のブラウザに保存されます。

## 開き方

### iPhone・iPad・Mac のアプリ

`apple/` に、同じ中身の **SwiftUI アプリ**を置いてあります。
ひとつのプロジェクトで iPhone・iPad・Mac の3つに入り、
**登録した地点と提供元の色は iCloud で行き来します**。

```bash
open apple/WeatherAH.xcodeproj
```

入れ方と iCloud 同期の設定は [apple/README.md](apple/README.md) にあります。
Mac で動かすだけなら Apple ID があれば十分で、費用はかかりません。

### そのまま使う

上のURLを開くだけです。スマホのホーム画面に追加しておくと便利です。

### 1ファイル版（ネットの置き場所なしで使う）

`dist/weather-app.html` をダウンロードしてダブルクリックするだけです。
作り直すときは `python3 scripts/build_single.py`。

ただし `file://` で開くとブラウザの決まりで**現在地の取得が使えません**。
画面の「地点を手で設定する」から緯度・経度を入れてください（既定は宇都宮）。

### 手元でサーバを立てる

```bash
php -S 127.0.0.1:8080 -t docs
python3 -m http.server 8080 --directory docs
```

→ http://127.0.0.1:8080/

現在地の取得（Geolocation）は **https か localhost** でしか動きません。

## データの出どころ

| 提供元 | 内容 | 取り方 |
|---|---|---|
| 気象庁 | アメダス実況（気温・湿度・気圧・風・降水）、直近の10分値 | ブラウザから直接 |
| 気象庁 | 府県天気予報（3日・週間の天気／気温／降水確率／気象概況） | ブラウザから直接 |
| 気象庁MSM・GSM（Open-Meteo経由） | 1時間ごとの気温・湿度・雨量の予報 | ブラウザから直接 |
| Open-Meteo（総合） | 1時間ごとの降水確率 | ブラウザから直接 |
| Yahoo!天気 | 今日・明日の3時間ごとの気温・湿度・雨量／6時間ごとの降水確率／6日先までの日別 | サーバ側で取り込み（3時間おき） |
| ウェザーニュース | 実況の気温・湿度・気圧／1時間ごとの気温と雨量（3日先まで）／午前・午後の降水確率 | サーバ側で取り込み（3時間おき） |

### なぜ Open-Meteo を使っているか

気象庁が公開している府県天気予報には**湿度が入っていません**。
そのため、絶対湿度の「予報」を出すには数値予報モデルの値が要ります。
Open-Meteo は気象庁の数値予報（MSM・GSM）をそのまま配信していて、
APIキーなしで、ブラウザから直接読める形（CORS対応）で提供しています。
つまり中身は気象庁のデータで、受け取り口だけを借りている形です。

ただし**降水確率だけは気象庁のモデルに入っていません**。
`models=jma_seamless` を付けて頼むと、降水確率は中身が空で返ってきます
（`jma_msm` / `jma_gsm` も同じです）。そのため降水確率だけは、
モデルを指定せずに **Open-Meteo が各社のモデルをまとめて出している値**をもらっています。
グラフや表では「気象庁MSM/GSM」の列に入りますが、出どころが違うため
画面の注記にもそのことを書いてあります。

### Yahoo!天気とウェザーニュースの取り方

どちらも一般に公開されたAPIがなく、**ブラウザから直接は読めません**（CORSで止まります）。
そこで GitHub Actions が3時間おきにページを取得し、読み取った値を
`docs/data/latest.json` に書き出しています。アプリはそのファイルを読みます。

ページから取れるものには差があります。

- **Yahoo!天気** … 今日と明日の3時間ごとの気温・湿度。表が「今日」「明日」の
  2つに分かれているので、両方を読んでつなげています。
- **ウェザーニュース** … 実況の気温・湿度・気圧と、1時間ごとの気温（3日先まで）。
  1時間ごとの**湿度は項目自体がありません**。2週間天気のページも画面側で
  組み立てられていて読めなかったため、日ごとの値は1時間予報からまとめています。

### 1週間の予報が取れる範囲

| 提供元 | 先何日まで | 出どころ |
|---|---|---|
| 気象庁 | 約7日 | 府県天気予報の週間 |
| 気象庁MSM/GSM | 10日 | 1時間ごとの予報から日ごとにまとめた計算値（降水確率のみ Open-Meteo の総合予報） |
| Yahoo!天気 | 6日 | ページの週間表 |
| ウェザーニュース | 約3日 | 1時間ごとの予報から日ごとにまとめた計算値 |

ページの作りが変わると読めなくなります。そのときは `latest.json` に理由が残り、
アプリの「取得状況」に**失敗**と出ます。気象庁と数値予報は影響を受けません。

原因を調べる道具として `scripts/probe.py` を置いてあります。
「ページの作りを調べる」ワークフローから動かすと、いまページがどうなっているか
（表の見出し、値の入っている場所、ページが呼んでいるAPI）がログに出ます。

## ブラウザで描画してから読み取る（任意）

ウェザーニュースの1時間ごとの予報は、ページを開いてから画面側で組み立てられます。
ページのHTMLを取ってくるだけでは読めないため、**本物のブラウザにページを開かせて、
描画が終わってからHTMLを取り出す**仕組みを用意しました。

```bash
pip install playwright && playwright install chromium
python3 scripts/collect_browser.py --dump   # 描画後に何があるか見るだけ
python3 scripts/collect_browser.py          # latest.json に足す
```

**外し方**は次のどちらでも構いません。どちらも `collect.py` だけの動きに戻ります。

- `scripts/settings.json` の `sources.<名前>.browser.enabled` を `false` にする
- `.github/workflows/weather-collect.yml` の「ブラウザで取り込む」ステップを消す

この仕組みは**読めたぶんだけ足す**作りです。失敗しても `latest.json` は壊れませんし、
Playwright が入っていない環境では何もせずに正常終了します。ページの作りが変わって
読めなくなっても、気象庁と数値予報、Yahoo!天気の取り込みには影響しません。

## 地点を増やすには

### アプリ側（気象庁・数値予報）

画面の「地点を追加・編集する」を開いて、名前と緯度・経度を入れて **新しい地点として追加**。
緯度・経度は地図アプリで長押しすると出てきます。「現在地を入れる」でいまいる場所を入れることもできます。
**気象庁とMSM/GSMは、登録した地点ならどこでもそのまま動きます。**

### 取り込み側（Yahoo!天気・ウェザーニュース）

この2社はページから読むので、地点ごとにURLが要ります。
`scripts/settings.json` の `places` に足してください。

```json
{
  "places": [
    { "id": "utsunomiya", "label": "栃木県宇都宮市", "lat": 36.5551, "lon": 139.8828,
      "sources": { "yahoo": { ... }, "weathernews": { ... } } },
    { "id": "tokyo", "label": "東京都千代田区", "lat": 35.6812, "lon": 139.7671,
      "sources": { "yahoo": { ... }, "weathernews": { ... } } }
  ]
}
```

`lat` / `lon` はアプリ側の地点と突き合わせるために使います。アプリは**一番近い取り込み地点**の値を使い、
40kmより離れていたら使いません（そのときは「取得状況」に距離が出ます）。
気象庁とMSM/GSMは影響を受けないので、取り込みを足していない地点でも使えます。

```bash
# 書き出さずに読めるかどうかだけ試す
python3 scripts/collect.py --dry-run

# 保存したページで読み取りを試す
python3 scripts/collect.py --html yahoo=saved.html --dry-run

# 本番（docs/data/latest.json に書き出す）
python3 scripts/collect.py

# ページの作りを調べる
python3 scripts/probe.py --tables "https://…"
python3 scripts/probe.py --around "https://…" --pattern "湿度"
```

取り込みの間隔を変えるときは `.github/workflows/weather-collect.yml` の
`schedule` を直してください。止めたい場合は各地点の `enabled` を `false` にします。

## 降水確率の当たり具合

各社の降水確率が実際に当たったかどうかを、`scripts/verify.py` が数えています。

```bash
python3 scripts/verify.py            # 予報を書きためて、終わった期間を照合する
python3 scripts/verify.py --no-fetch # 書きためるだけ（外に出ない）
```

やっていることは3つです。

1. いまの予報の降水確率を `docs/data/history.json` に書きためる。
   同じ期間の予報は上書きし、**その期間が始まる前の最後の予報**を残します。
2. 終わった期間について、気象庁アメダスの実際の降水量を足す。
3. 予報と実際をつき合わせて、`docs/data/accuracy.json` に書き出す。

| 決めごと | 中身 |
|---|---|
| 期間の切り方 | 7日前〜4日前は1日ごと、直近3日は半日ごと（0〜12時／12〜24時） |
| 「雨が降った」 | アメダスの雨量が **1mm以上**（気象庁の降水確率の定義に合わせています） |
| 「降る予報」 | 降水確率 **50%以上** |
| ブライアスコア | 確率そのもののずれ。`(確率−実際)²` の平均で、0に近いほど的確 |

刻みは提供元で違うため（気象庁6時間・Yahoo!天気6時間・ウェザーニュース午前午後・数値予報1時間）、
その期間に**重なる区切りのうち一番高い値**を使います。
刻みが細かい提供元ほど高めに出やすいので、比べるときは頭に置いてください。

**過去の予報はどの提供元からもあとから取り寄せられません。**
そのため数字は、取り込みが動きはじめてから1週間ほどでそろいます。
それまでは「まだ数えられません」と出ます。

実際の雨量は、緯度経度から近い順に観測所をあたり、**雨量が実際に読める観測所**を選びます
（風だけを測っている観測所もあるためです）。

## 計算式

| 量 | 式 |
|---|---|
| 飽和水蒸気圧 | `es = 6.1078 × 10^(7.5t/(t+237.3))` [hPa]（Tetens） |
| 水蒸気圧 | `e = es × RH/100` [hPa] |
| 容積絶対湿度 | `216.68 × e /(t+273.15)` [g/m³] |
| 重量絶対湿度 | `621.945 × e /(P−e)` [g/kg(DA)] |
| 露点温度 | Magnusの式 |
| 不快指数 | `0.81t + 0.01RH(0.99t−14.3) + 46.3` |

気圧 `P` は観測値があればそれを、なければ観測所の標高から推定した値を使います。

## CSS・JavaScript を直したら

ブラウザは同じURLのファイルをしばらく使い回します。中身を直しても
URLが同じだと古いままになり、画面と動きが食い違います。
中身から作った印を付け替えてください。

```bash
python3 scripts/stamp_assets.py     # docs/index.html の ?v=… を付け替える
```

`python3 scripts/build_single.py` を実行すると、これも一緒に行われます。

## 注意

- 表示する値は目安です。設計や気密測定の判断に使うときは実測値と照らし合わせてください。
- 気象庁のアメダスは全地点が湿度を測っているわけではありません。
  アプリは**気温と湿度がそろっている一番近い観測所**を選び、その距離を画面に出します。
